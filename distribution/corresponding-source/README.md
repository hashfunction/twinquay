# TwinQuay corresponding-source preparation

This is a source-acquisition and provenance audit for Windows run **34671787439**, public source **04253cf3a14d1fd3ee2f153be14e01bdcc9122cc**, local source **f98d281a07e80e8115dbbf681dc8e0e3a052602b**. It is **not a public source release, final Store package receipt, or license-clearance claim**. The run passed its actual installed scan/quarantine/conflict/restore, module, normal-close and owned-uninstall qualification; those results do not establish source/license fulfillment.

All 79 archive inputs in `source-manifest.json` were actually downloaded and measured. PyPI inputs were checked against the version-specific PyPI SHA-256/length; Qt module inputs against Qt's version-specific Metalink SHA-256/length. Python, Mesa and LLVM came from their official version-specific release directories, with measured hashes. GitHub source archives are pinned to resolved upstream commit IDs, not moving tags. Signatures were not independently verified. `binary-provenance` inputs are private comparison inputs, **never corresponding-source assets**.

The preparation cache is `/private/tmp/twinquay-corresponding-source/downloads` on the audit host. It contains approximately 879 MB, including six compressed Qt module archives. Do not unpack QtWebEngine on a low-space host: its 580,351,104-byte archive contains Chromium/PDFium and is much larger unpacked. Upstream license references and inspection records remain under the adjacent `notices/` and `metadata/` directories.

## Recheck or acquire

From the TwinQuay source root, with Python 3.10 or later:

```sh
python distribution/corresponding-source/test_materials.py -v
python distribution/corresponding-source/materials.py fetch --cache /path/to/source-cache
python distribution/corresponding-source/materials.py verify --cache /path/to/source-cache
```

`fetch` downloads only the 71 **source** archives by default. It refuses corrupt existing files, different bytes, oversized downloads, unsafe filenames and non-HTTPS sources. It installs a cache file only after verification and never unpacks or executes an archive. Use the OS's normal trusted CA configuration. Do not disable TLS verification.

To materialize the 287 byte-checked source-license reference files (about 1.8 MB) into a new directory:

```sh
python distribution/corresponding-source/collect-notices.py --cache /path/to/source-cache --output /path/to/new-notice-directory
python distribution/corresponding-source/test_notices.py -v
```

The collector verifies each source archive and exact license member before creating output; it refuses an existing destination. Its `NOTICE-INDEX.json` preserves the reference-only scope and clearance=false. This is a conservative reference collection, including optional/tool licenses; final configured PDF attributions and Microsoft redistribution evidence still need review.

For the complete audit comparison, also acquire the eight binary-provenance archives and supply the original artifact inventory:

```sh
python distribution/corresponding-source/materials.py fetch --cache /path/to/source-cache --include-binaries
python distribution/corresponding-source/materials.py verify --cache /path/to/source-cache --include-binaries --inventory /path/to/run-34671787439/package-inventory.json
```

The expected result is **79 verified archives; 114 native files, 66 exact upstream binary matches and 48 unmatched entries**. Of the 48, four are explained local build outputs (the PyInstaller executable and three C extensions); **44 are unresolved UCRT/API-set binary origin records**. The helper always reports source/publication/release clearance as false. It checks the complete native path set, each installed hash/length, the inventory's exact source commit and file hash, and each matching member inside the actual wheel/CPython ZIP. The standalone Qt-signed Mesa archive was additionally checked with `tar -xOf ... opengl32sw.dll`: SHA-256 `b04de4541863bc7d8879040a78889c4849c1b1da2784c4630f734c146c2998ce`, identical to both the wheel and installed inventory.
